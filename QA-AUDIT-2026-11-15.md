# Audit et QA 0.1.9

Cette passe porte sur les blocages de tâches, les exports, les erreurs de l’interface et le diagnostic Windows. Elle ne certifie pas l’absence de bugs dans tout le logiciel.

## Correctifs

- Rendu sur chemins accentués : copie explicite des fichiers du bundle afin de conserver index.html même avec l’ancien copieur de répertoires Windows de Node. Test de régression Unicode.
- Export CapCut : progression globale pondérée, phases de préparation et assemblage. Les rendus intermédiaires ne remettent plus la barre à zéro. Tests de préparation et export complet sur projets factices.
- File de tâches : les exceptions synchrones ou asynchrones des observateurs et callbacks de fin ne bloquent plus les tâches suivantes.
- Transport API : une réponse HTML ou un JSON invalide ne passe plus pour une réponse réussie. Les erreurs IA connues gardent leur parcours de récupération.
- Suppression des prompts temporaires : une erreur persistante de verrouillage Windows ne remonte plus depuis les événements du processus. Trois tentatives au maximum, sans masquer l’erreur initiale.
- Import de rushes : fermeture du premier descripteur si le deuxième fichier ne peut pas être ouvert ; nettoyage du fichier temporaire après comparaison ou renommage en échec.
- Traduction : les mutations de texte sous data-no-tr restent protégées, y compris les logs techniques.

## Signalement volontaire

Une erreur inattendue de tâche, de page, de connexion ou un blocage de fenêtre propose de préparer un rapport. Le moteur conserve un tampon borné ; aucune vidéo, aucun projet, aucune conversation IA complète ne sont joints. Chemins personnels, secrets connus, en-têtes d’authentification, paramètres d’URL et noms de projets sont masqués. Le nettoyage n’est pas une garantie d’anonymat : l’aperçu permet une vérification avant copie, téléchargement ou ouverture du client mail.

Destinataire fixe : hello@contact.cliffiscurious.com. Aucun envoi automatique. Le protocole mailto est limité à ce destinataire et aux champs subject/body ; les pièces jointes et destinataires additionnels ne sont pas autorisés par le shell.

## Limites à suivre

- Installateur Windows toujours non signé, en l’absence de certificat.
- Un arrêt de processus dépend du système d’exploitation ; ne pas déclarer une tâche arrêtée avant la fin effective de son écrivain.
- Un verrou persistant peut laisser un prompt temporaire après les trois tentatives. Le journal technique indique l’échec de nettoyage sans publier le chemin.
- Le client mail doit être configuré ; le téléchargement TXT et la copie restent disponibles.
- Les tests utilisent des projets synthétiques et des fournisseurs simulés, sans envoyer de mail ni modifier les projets du créateur.

## Vérifications

269 tests unitaires du studio, 213 du rendu (dont la copie Unicode), 61 du lanceur Windows et 58 tests Python CapCut réussis. Tous les packages passent TypeScript. Le parcours du signalement a été contrôlé dans Chromium à 1440 × 900 et 1280 × 720 : ouverture manuelle, aperçu, copie simulée, vrai téléchargement TXT, masquage des secrets d’un processus factice en échec, secours hors connexion. Aucun mail envoyé.

Pour les tests E2E de rendu, utiliser un profil utilisateur temporaire et le Node embarqué vérifié. Une DA personnelle active change légitimement les overlays du projet synthétique : ne pas laisser les tests lire le profil du créateur. Les caches de modèles peuvent être réutilisés en lecture.

Les résultats d’exports complets et la publication effective sont consignés dans la release ; ce document ne vaut pas preuve de publication.
